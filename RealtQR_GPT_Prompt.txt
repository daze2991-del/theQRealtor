I have been building a SaaS product called RealtQR with Claude (Anthropic).
It is a lead capture + QR sign tracking system for real estate agents at open houses.

WHAT REALTQR DOES
─────────────────
- Agents create a property and generate one QR code per physical sign 
  (Front Sign, Corner Sign, Directional Sign, etc.)
- Each QR code links to: /p/{propertyId}?qr={qrId}
- When a visitor scans the QR at an open house, they see a landing page
  with the property address and a lead capture form (name, phone, email)
- On submit: the lead is saved to the database WITH the QR code ID attached
  (so we know exactly which sign generated the lead)
- An SMS is sent to the visitor via Twilio
- Agents see a dashboard with scan counts, leads, and a live sign placement 
  map (OpenStreetMap / Leaflet) showing where each sign is physically placed

DATABASE SCHEMA (Supabase / PostgreSQL)
────────────────────────────────────────
Table: profiles
  id          uuid (references auth.users)
  email       text
  name        text
  plan        text  -- 'free' or 'pro'
  created_at  timestamp

Table: properties
  id          uuid primary key default gen_random_uuid()
  user_id     uuid references profiles(id)
  address     text
  agent_name  text
  active      boolean default false   -- open house live toggle
  created_at  timestamp default now()

Table: qrcodes
  id          uuid primary key default gen_random_uuid()
  property_id uuid references properties(id) on delete cascade
  label       text   -- e.g. "Front Sign", "Corner Sign"
  scan_count  integer default 0
  lat         float
  lng         float
  created_at  timestamp default now()

Table: leads
  id          uuid primary key default gen_random_uuid()
  property_id uuid references properties(id)
  qr_id       uuid references qrcodes(id)
  name        text
  phone       text
  email       text
  created_at  timestamp default now()

Table: scan_events
  id          uuid primary key default gen_random_uuid()
  qr_id       uuid references qrcodes(id)
  lat         float
  lng         float
  created_at  timestamp default now()

const exportCSV = (leads, properties, qrcodes) => {
  const rows = [["Name","Phone","Email","Property","Sign","Date"]];
  leads.forEach(l=>{
    const prop = properties.find(p=>p.id===l.property_id);
    const qr   = qrcodes.find(q=>q.id===l.qr_id);
    rows.push([l.name, l.phone, l.email, prop?.address||"", qr?.label||"", fmtDate(l.created_at)]);
  });
  const csv  = rows.map(r=>r.map(c=>`"${String(c).replace(/"/g,'""')}"`).join(",")).join("\n");
  const blob = new Blob([csv],{type:"text/csv"});
  const url  = URL.createObjectURL(blob);
  const a    = document.createElement("a");
  a.href=url; a.download="realtqr-leads.csv"; a.click();
  URL.revokeObjectURL(url);
};

1. The Leaflet map components MUST be dynamically imported with 
   { ssr: false } because Leaflet requires window to be defined.
   Example:
     const LeafletSignMap = dynamic(() => import('@/components/LeafletSignMap'), { ssr: false })

2. The QR landing page at /p/[propertyId] is PUBLIC — no auth required.
   Visitors who scan a QR code should see the lead form without logging in.

3. The scan_count increment should happen server-side in an API route,
   not from the client, to prevent manipulation.

4. The SMS send should happen in a server-side API route (/api/send-sms)
   so Twilio credentials are never exposed to the client.

5. Use Supabase RLS so users can only read/write their own properties,
   QR codes, and leads. The leads table is slightly different — it needs
   to be writable by anonymous users (visitors submitting the form)
   but only readable by the agent who owns the property.

6. The design uses inline styles throughout (not Tailwind or CSS modules).
   Keep it that way unless the person explicitly asks to switch.
